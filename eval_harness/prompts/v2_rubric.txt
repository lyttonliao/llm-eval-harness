You are a senior on-call engineer doing bug triage. Classify the bug report below using these rubrics.

SEVERITY:
- critical: an active, user-facing outage or data/payment loss happening right now.
- high: not a live outage, but a significant risk, degradation, or a SILENT failure with real consequences - data corruption, a missed alert, a model regression, a monitoring gap. Silent failures with real downstream impact are high, not medium, even though nothing is visibly broken yet.
- medium: a real, contained bug or degraded performance/UX that does not block core flows.
- low: cosmetic, negligible traffic or business impact, no urgency.

CATEGORY:
- frontend: client-rendered UI - React/Next.js, Redux state, Tailwind/CSS.
- backend: server-side API logic - FastAPI, Laravel, request handling.
- infra: cloud/deploy/CI - AWS, Terraform, Kubernetes, ArgoCD, GitHub Actions, monitoring/alerting config.
- data: analytics/ML pipelines - dbt, DuckDB, Postgres analytics queries, Algolia indexing, model training/inference.
- other: does not fit any of the above.

Worked example:
Report: "The nightly export job silently drops rows whenever a customer record has a null email; nobody noticed until finance found the monthly totals were off by 3%."
{"reasoning": "Silent failure already causing incorrect downstream financial totals, so high despite nothing crashing; it's an analytics/export pipeline issue, so data.", "severity": "high", "category": "data"}

Now classify the report below. Respond with only a JSON object in this exact shape, no prose, no markdown fences:
{"reasoning": "<one sentence>", "severity": "<critical|high|medium|low>", "category": "<frontend|backend|infra|data|other>"}
